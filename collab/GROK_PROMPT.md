# Grok 협업 지시문 (Grok ↔ Claude)

> 운영자(민구님, 비개발자)가 정한 협업 규칙. 저장소: https://github.com/P-Max168/thai-news-kr (사이트: https://p-max168.github.io/thai-news-kr/)
> 이 파일이 최신 기준이다. 규칙을 바꿀 땐 운영자 승인 후 이 파일을 고친다.

## 0. 한 줄 요약
- **Grok = 매일 콘텐츠**(수집·번역·판 작성·정기 실행·배포). **Claude = 점검·수정**(Grok의 실수와 놓친 것을 찾아 고침).
- 위험하지 않은 일은 **각자 알아서 판단해 처리**하고 짧게 기록한다. 운영자에게는 **정말 필요한 것만** 묻는다.
- 서로 같은 파일을 동시에 고치지 않는다. 모든 소통은 아래 `collab/` 파일에 남긴다.

## 1. 역할 분담
| | Grok | Claude |
|---|---|---|
| 정기 실행 | **07:08 아침판 / 18:08 저녁판 (Grok이 계속 맡음)** | 하지 않음 |
| 뉴스 수집·번역·판 작성 | **Grok** (`tools/editions/*.py`, `data/<날짜>-am\|pm.json·js`, `data/index.*`, `data/issues.*`, `og/`, `e/`) | 하지 않음 |
| 배포(판) | `bash tools/deploy.sh` | 하지 않음 |
| 점검 | 자기 판을 `newslib check` 로 검증 | **Grok의 판·코드를 읽고 실수(번역 오류, 깨진 링크, 빠진 필드, 형식 오류, 화면 버그) 찾기** |
| 수정 | 자기 판의 오류 | **찾은 문제를 별도 브랜치에서 고쳐 반영** (판 데이터의 명백한 오류 포함) |
| 화면·코드 | 직접 고치지 않음(요청만) | `index.html`, `assets/*`, `sw.js`, `manifest.json`, 안내 4쪽, `.github/workflows/*`, `tools/*`(editions 제외), `firestore.rules`(파일만) |
| 감시 | 판이 늦으면 스스로 재시도 후 운영자에게 알림 | 판 지연·자동 갱신·사이트 상태 확인 후 `collab/STATUS.md` 에 기록 |

**아무도 손대지 않는 것**: `data/korea.json|js`, `data/ticker.json|js` (GitHub Actions 봇 전용, 2시간마다 갱신).

## 2. 승인 기준 (운영자는 정말 필요한 때만)
| 구분 | 예시 | 처리 |
|---|---|---|
| **알아서 함** | 오타, 깨진 링크, 화면 버그, 스크립트 오류, 속도 개선, 문서 정리, 판 오류 수정 | 검사 통과 시 바로 반영하고 `collab/LOG.md` 에 한 줄 |
| **운영자에게 먼저 물음** | 검색엔진 차단(noindex·robots) 해제, 법적 문구 확정, 운영자 이름으로 나가는 글, 광고·애드센스·결제, 개인정보 수집 방식 변경, 기능 삭제, 되돌리기 어려운 변경 | 승인 전엔 손대지 않음. `PENDING_APPROVAL.md` 에 적고 운영자에게 보고 |
| **로그인 필요(AI는 못 함)** | Firebase 규칙 게시, 애드센스 신청, 앱 스토어 등록 | 무엇을 어디서 하면 되는지만 운영자에게 알림 |

## 3. 공유 저장 경로 (모두 이 저장소 안, 없으면 만든다)
| 경로 | 용도 | 쓰는 사람 |
|---|---|---|
| `collab/STATUS.md` | **현재 상태판**: 마지막 판, 진행 중인 작업, 지금 어떤 파일을 누가 잡고 있는지(잠금) | 둘 다, 항상 최신 1개 표만 유지 |
| `collab/REQUESTS.md` | **서로에게 요청**: `[Grok→Claude]` / `[Claude→Grok]` 한 줄씩 (무엇이·어디서·언제 터지는지·상태) | 둘 다 |
| `collab/LOG.md` | **작업 기록**(추가만, 기존 줄 수정·삭제 금지): `시각(date 출력) · 누가 · 바뀐 것 · 원인→재발 방지 · 확인 여부` | 둘 다 |
| `DEV_LOG.md` | 기존 개발 기록(기존 형식 유지, 맨 아래에 줄 추가만) | 둘 다 |
| `PENDING_APPROVAL.md` | 운영자 승인 대기 목록(기존 방식 그대로) | 둘 다 |
| `/workspace/...` (Grok 서버 폴더·로그) | Grok 전용 실행 환경. Claude는 접근 못 함 → **필요한 내용은 `collab/STATUS.md` 로 옮겨 적는다** | Grok |

## 4. 충돌 방지 규칙
1. **작업 시작 전** 최신 main 을 받는다(`git pull`). 봇이 2시간마다 커밋하므로 항상 뒤처질 수 있다.
2. **force push, `reset --hard`, 남의 커밋 다시 쓰기 금지.**
3. 같은 파일을 둘이 동시에 고치지 않는다. 시작 전 `collab/STATUS.md` 의 '잠금' 칸에 `파일 · 누가 · 시각` 을 적고, 끝나면 지운다. 상대가 잡고 있으면 `REQUESTS.md` 에 요청만 남긴다.
4. **Grok**: 판 데이터(`data/` 의 판 파일)는 지금처럼 main 에 바로 올린다. 코드·설정이 필요하면 직접 고치지 말고 요청한다.
5. **Claude**: 별도 브랜치(`claude/<주제>`)에서 고치고, '알아서 함' 항목은 검사 통과 후 합친다. 합칠 땐 항상 최신 main 위에서.
6. **시간 금지 구간**(방콕): 07:00~08:10, 18:00~18:40 에는 판 빌드 외 push 금지(둘 다).
7. 판 데이터의 오류를 Claude가 고칠 땐 **판 id·기사 id·무엇을 왜 고쳤는지**를 `collab/LOG.md` 와 `collab/REQUESTS.md` 에 남겨, Grok이 다음 판에서 같은 실수를 반복하지 않게 한다.
8. 시각은 `date` 출력만 쓴다(예정·어림 시각 금지). 확인 못 한 것은 '미확인'으로 적는다.

## 5. Grok이 지금 먼저 할 일 (작업 시작 전 `collab/STATUS.md` 에 답)
1. 07:08/18:08 정기 실행이 지금 켜져 있나? 마지막 성공 시각은?
2. 최신 판이 `2026-10-05-am` 에서 멈춰 있다(10-05 저녁판·10-06 아침판 없음). 원인은? (`/workspace/logs/automation.log`, `edition-stale.txt` 근거)
3. 진행 중이거나 올리지 않은 변경(stash 포함)이 있나?
→ 답이 올라온 뒤 정기 실행을 재개하거나 누락된 판을 만든다. 누락 판은 원래 슬롯 id(`-pm`/`-am`)로 만든다(README '판 파일 이름 규칙').

## 6. 소통 예시
- `REQUESTS.md`: `[Claude→Grok] 10-06 · 2026-10-05-am · ea2 · 원문 URL 404 · 상태: 대기`
- `LOG.md`: `2026-10-06 14:50 · Claude · assets/app.js 줄바꿈 오류 수정 · 원인: … → 재발 방지: … · 확인: 로컬 검사 통과`
