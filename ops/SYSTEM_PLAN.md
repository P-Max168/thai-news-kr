# 뉴스 시스템 전체 설계 (2026-10-23 맥스님 확정, Claude 작성)

> 모든 AI(그록·GPT·Claude)는 이 저장소 작업 전에 이 문서와 `collab/STATUS.md` '최근 인수인계'를 먼저 읽는다.
> 이 문서는 "앞으로 바꿀 계획"이다. 아직 적용 안 된 항목은 각 단계의 상태 칸을 본다.

## 0. 기본 원칙
- 코드가 할 수 있는 일은 전부 코드가 한다. AI는 "판단(고르기)과 글쓰기"만 한다.
- 엔진은 하나, 판은 설정 파일로 늘린다(저장소 통째 복사 금지).
- 어떤 AI가 멈춰도 판은 나간다(Claude 비상 발행).
- 그록 토큰은 아낀다(맥스님 요청). 그록에게는 코드가 줄여 놓은 재료만 준다.

## 1. 구조
- 공통 엔진: 수집 → 걸러내기 → 원문 본문 확보 → 빌드 → 자동 검사 → 발행 → 누락 감시 → 측정 기록
- 판 설정 파일(판마다 1개): 출처 나라, 독자 언어, 발행 시각(시간대), 금액 표기, 주제 가중치, 번역 규칙 파일, 주소, 담당 AI, 백업 AI
- 수집처 목록: 태국(`tools/sources.json`, 있음), 한국(일부 있음), 베트남(새로 만듦)
- 새 판 추가 = 설정 파일 1개 + 번역 규칙 1개

## 2. 판 하나가 나가는 흐름
| 시각 | 누가 | 하는 일 |
|---|---|---|
| 발행 30분 전 | 코드 | 수집 → 중복·이미 낸 기사·오래된 기사 제거(후보 30~40건) → 원문 본문까지 가져와 "재료 상자"에 저장 |
| 발행 20분 전 | 담당 AI | 저장소에 "시작" 표시 → 재료 상자만 보고 고르기 + 원고 작성 → 저장 |
| 바로 뒤 | 코드 | 자동 검사(형식 오류는 코드가 고침) → 통과 시 발행 |
| 발행 시각 | Claude | 시작 표시가 없으면 즉시 비상 발행 |
| 발행 30분 뒤 | Claude | 시작은 했는데 판이 없으면 이어받음 |
| 항상 | 코드 | 판마다 자료량·소요시간·재작업 횟수·멈춤 여부 기록 |

- 비상 발행 시작 시 "Claude 발행 중" 표시를 먼저 건다 → 늦게 깬 담당 AI는 이 표시를 보면 멈춘다(중복 방지).
- 비상 발행이 끝나면 `collab/STATUS.md`에 "Claude 비상 발행, 이유" 기록.
- "지연 발행" 라벨: AI가 손으로 붙이지 않는다. 코드가 예정 시각과 실제 발행 시각을 비교해 자동으로 붙인다.

## 3. 역할
| 누구 | 맡는 일 |
|---|---|
| 코드(GitHub Actions) | 수집, 걸러내기, 원문 확보, 검사, 발행, 감시, 측정 |
| 그록 | 태국 뉴스 고르기 + 원고 작성 + X 화제 참고 |
| 추가 언어 번역 | 처음엔 그록이 같이. 측정 결과 보고 GPT로 나눌지 결정 |
| 한국·베트남 출처 판 | GPT 후보(그 판을 열 때 결정) |
| Claude | 모든 판 비상 발행 + 개발 |
| 제미니 | 자동 흐름 제외(예약 작업은 결과 저장 불가, 10-23 확인) |
| 맥스님 | 승인과 결정 |

- 고르기와 첫 언어 원고는 같은 AI가 한다(둘 다 원문을 읽어야 함 → 나누면 원문을 두 번 읽어 토큰 2배).
- 두 번째 언어부터는 완성 원고만 보고 번역하므로 다른 AI에 넘겨도 손해 없음.
